# メルカリShops HTTP読取クライアントの確認（2026-10-11）

`webHttpReadOnlyClient.ts` はサーバー専用で、送信先を `mercari-shops.com` の既知の2パスに固定する。本人認証済みの生ID/更新トークンを呼出元から受け、観測済みのIDP引渡し後、`Self`、`OwnShops`、既知のB005396下書き2件をこの順で読む。Cookieはプロセス内だけで保持し、戻り値には値を含めない。HTTPリダイレクトを追わず、タイムアウトを設定する。下書きの作成・更新・公開処理は含まない。

型検査とモック検査は通過した。モックでは送信先と操作名、対象店舗が一致しない場合の停止、下書きID不一致での停止、リダイレクト・Cookie欠落・期限切れでの停止を確認した。

本人提供HARのIDP引渡し値を**一時プロセスのメモリ内だけ**で読み、期限を確認して、ローカルから1回実通信した。IDP引渡しはHTTP 200だったが、新クライアントのCookie属性検証で `COOKIE_UNVERIFIED` となり停止した。`Self`、`OwnShops`、下書き2件の追加通信はこの回では行っていない。返されたCookieの名前・値・属性やトークンは出力・保存していないため、どの属性が条件に合わなかったかは未特定。再送はしていない。

以前の一回限りのローカル検証では、同じIDP引渡しから `Self` 読取まで成功した。ただし今回の実装に必要なCookie属性と対象店舗の権限、下書き2件の読取、BELLOのAmplify実行環境での動作は未確認。従ってこのクライアントを実運用の出品経路に接続せず、B005396の既存下書きに対する新規作成も許可しない。
