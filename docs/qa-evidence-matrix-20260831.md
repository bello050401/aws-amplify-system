## 6. 検証が途中で止まった理由（重要・訂正）

監査の終盤で、保存していたStagingのADMINセッションが無効になった:

```
POST cognito-idp.us-west-2.amazonaws.com  GetTokensFromRefreshToken
→ 400 {"__type":"NotAuthorizedException","message":"Refresh Token has been revoked"}
```

以降のブラウザ操作はすべて `/inventory/login` へ転送されていた。

**そのため、最後に流した「最終検証」の3セクションは検証として成立して
いない** — HTTP 200・hydration 0件・5xx 0件という数字は出ているが、
それは**ログイン画面を測った結果**であり、アプリ本体の画面ではない。
ここで「問題なし」と報告していたら誤報になっていたため、明示的に訂正
しておく。

セッションが生きていた時点までの検証（上記1〜4節）はすべて有効。
最後に有効だったのは詳細検索・直接編集・ルート一覧の確認で、
いずれも実データと「管理者 (ADMIN)」表示を伴っている。

### この時点で実機未確認のまま残ったもの

| 項目 | 現状 | 必要なこと |
|---|---|---|
| 加工結果の「確認して採用する」 | ロジックを`pickPendingReviewVersion`として切り出し、**10件のテストで固定**(最新のNEEDS_REVIEWを選ぶ / READY時は出さない / 空なら出さない / 処理中・失敗時は出さない)。ビルド・型・lintは通過 | **Staging再ログイン後に1回押すだけ** |
| 価格変更履歴の表示 | 実装済み・ビルド通過。ただし**ChannelListingが0件**のため、そもそも親セクション(AutoPricingSection)が描画されない | EC出品対象カテゴリの商品でMercari設定を保存してChannelListingを作れば表示される |
| 日本語404ページ | **AWS_VERIFIED** — 実機で HTTP 404 /「お探しのページは見つかりませんでした」 | 完了 |

### 副次的に見つけて直したもの

画像加工パネルは、版一覧の取得に失敗すると**パネルごと消えていた**
(`byKey === null` で `return null`)。`setError`の表示先がその消える
JSXの中にあるため、**エラーが誰にも見えない**構造だった。実際に今回の
セッション切れでは「パネルが最初から存在しない」ようにしか見えず、
原因の切り分けが遠回りになった。読み込み中／失敗のどちらかを必ず
表示するよう修正した。

## 7. セッションが切れた原因は不具合だった — **修正済み**

前節で「セッションが無効になった」と書いた件を追ったところ、**アプリ側の
不具合**であることが分かった。偶然ではなく、誰でも踏む経路だった。

このリポジトリは在庫管理(`/inventory`)と管理画面(`/admin`)の2つを載せて
おり、**Cognitoのセッションは両者で共有**されている。そして両方の
ログイン画面が、マウント時にこうしていた:

```ts
if (status === "signed-in-not-admin") {
  setError(NOT_ADMIN_MESSAGE);
  await signOut();          // ← ここ
}
```

つまり**在庫管理に正常ログインしている人が、管理画面のログイン画面を
開いた瞬間にサインアウトさせられる**。しかも `app/page.tsx` は
`redirect("/admin")` なので、**ドメインを直打ちした / トップをブックマーク
していた だけで踏む**。在庫側にも同じ形の実装があり、管理者が
`/inventory/login` を開くと管理画面のセッションを失う。

監査中に私自身がこれを踏み、Cognitoが
`NotAuthorizedException: Refresh Token has been revoked` を返すように
なって、以降のブラウザ検証がすべてログイン画面に対して行われていた。

**修正**: マウント時のサインアウトを両方から削除し、代わりに

- 権限が無いことの案内（従来どおり）
- **そのアカウントで実際に使える画面への導線**（在庫管理へ戻る / 管理画面へ戻る）
- 「別のアカウントでログインする」ボタン — **押したときだけ**サインアウト

とした。サインイン処理中の `UserAlreadyAuthenticatedException` からの
再試行（利用者が意図的に別アカウントで入ろうとしている場面）は従来どおり。

### 利用者への確認事項（product判断のため未変更）

`app/page.tsx` はルート `/` を **`/admin`** へ転送している。BELLOの
主用途が在庫管理であれば `/inventory` の方が自然だが、これは routing の
方針決定なので勝手には変えていない。上記修正によりセッションを失う実害は
無くなっているため、急ぎではない。
