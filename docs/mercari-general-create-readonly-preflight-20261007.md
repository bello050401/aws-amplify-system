# 一般商品のメルカリShops新規出品前の読取判定（2026-10-07）

`generalPrivateCreateRemotePreflight.mjs` は、既存商品との重複を調べるための**読取結果判定器**である。Shopsへアクセスする列挙器、保存、公開、新規作成のクリックは実装していない。判定結果はすべて `allowFinalCreate: false` であり、新規送信の許可証にはならない。既存の一回限りのclaimがあれば、遠隔読取より先に `LOCAL_CLAIM_UNKNOWN_NO_RETRY` で停止する。

## 現在の管理画面観測

- 正規Shops管理画面の「出品中」は `?tab=on_sale`、「下書き」は `?tab=draft`。出品中の公開状態は「すべて」を選べる。画面上の状態タブはこの2種類。
- 出品中の表は50行表示と、`pagination-next-button` / `pagination-prev-button` を観測した。URLはページ移動時に変わらない。次へを押した直後に**旧51 DOM行と両ボタン無効**が一時表示され、その後、新しい50行と両ボタン有効に変わった。無効表示を直ちに最終ページと判定してはいけない。全ページ数は未確認。
- 下書きは観測時点で12行、前へ・次へボタンなし。うち8行は商品名・画像代替文字列が空、価格0円、作成日時なしで、一覧から帰属を特定できない。これらを候補商品と無関係と断定できない。
- `keyword` 検索が商品管理コードを対象にするか未確認。検索0件はSKU不在の証明ではない。既知の商品IDに対する `EditProductPage` は読取実証済みだが、全一覧や下書きの列挙契約ではない。

## 判定器の境界

出品中・全公開状態と下書きの両方について、各ページの遷移前後の先頭ID変化、最大50行の本文件数、行ID群と次へ状態の2回の安定読取、終端状態を検査する。各行の商品ID・商品名・商品管理コードは、一覧表示と対象の編集画面の読取が一致したものだけを確定値として扱う。同じ管理コードまたは商品名を見つけたら `REMOTE_DUPLICATE_POSSIBLE`、ページ不足・不安定な表示は `REMOTE_SCAN_UNVERIFIED` / `REMOTE_SCAN_INCOMPLETE`、空欄で帰属不明の下書きは `REMOTE_DRAFT_AMBIGUOUS` とする。

全ページが安定していて一致が見えない場合も `NO_MATCH_IN_OBSERVED_UI` という**読取範囲の報告**に留める。画面外の商品、同時変更、管理コード未設定の既存商品、本人が別経路で作った下書きまで不存在と証明したことにはならない。現時点の8件の帰属不明下書きがあるため、通常の商品で安全な不在判定に到達できない。

実UI列挙器を作るには、次へクリック後の新旧行の識別と読み込み完了の独立した観測、全ページの安定した終端、各行から編集画面への正確なID遷移とSKU読取、空欄下書きの帰属を確認する方法が必要。これらを推測で埋めない。一般商品のCREATE最終クリックは引き続き封鎖し、将来その直前には同じ店舗の30秒送信gateを必須にする。
