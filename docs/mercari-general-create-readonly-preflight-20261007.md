# 一般商品のメルカリShops新規出品前の読取判定（2026-10-07）

`generalPrivateCreateRemotePreflight.mjs` は、既存商品との重複を調べるための**読取結果判定器**である。Shopsへアクセスする列挙器、保存、公開、新規作成のクリックは実装していない。判定結果はすべて `allowFinalCreate: false` であり、新規送信の許可証にはならない。既存の一回限りのclaimがあれば、遠隔読取より先に `LOCAL_CLAIM_UNKNOWN_NO_RETRY` で停止する。

## 現在の管理画面観測

- 正規Shops管理画面の「出品中」は `?tab=on_sale`、「下書き」は `?tab=draft`。出品中の公開状態は「すべて」を選べる。画面上の状態タブはこの2種類。
- 出品中の表は50行表示と、`pagination-next-button` / `pagination-prev-button` を観測した。URLはページ移動時に変わらない。次へを押した直後に**旧51 DOM行と両ボタン無効**が一時表示され、その後、新しい50行と両ボタン有効に変わった。無効表示を直ちに最終ページと判定してはいけない。全ページ数は未確認。
- 下書きは観測時点で12行、前へ・次へボタンなし。うち8行は商品名・画像代替文字列が空、価格0円、作成日時なしで、一覧から帰属を特定できない。これらを候補商品と無関係と断定できない。
- `keyword` 検索が商品管理コードを対象にするか未確認。検索0件はSKU不在の証明ではない。既知の商品IDに対する `EditProductPage` は読取実証済みだが、全一覧や下書きの列挙契約ではない。

## 判定器の境界

出品中・全公開状態と下書きの両方について、各ページの遷移前後の先頭ID変化、最大50行の本文件数、行ID群と次へ状態の2回の安定読取、終端状態を検査する。各行の商品ID・商品名・商品管理コードは、一覧表示と対象の編集画面の読取が一致したものだけを確定値として扱う。同じ管理コードまたは商品名を見つけたら `REMOTE_DUPLICATE_POSSIBLE`、ページ不足・不安定な表示は `REMOTE_SCAN_UNVERIFIED` / `REMOTE_SCAN_INCOMPLETE`、空欄で帰属不明の下書きは `REMOTE_DRAFT_AMBIGUOUS` とする。

全ページが安定していて一致が見えない場合も `NO_MATCH_IN_OBSERVED_UI` という**読取範囲の報告**に留める。画面外の商品、同時変更、管理コード未設定の既存商品、本人が別経路で作った下書きまで不存在と証明したことにはならない。現時点の8件の帰属不明下書きがあるため、通常の商品で安全な不在判定に到達できない。

実UI列挙器を作るには、次へクリック後の新旧行の識別と読み込み完了の独立した観測、全ページの安定した終端、各行から編集画面への正確なID遷移とSKU読取、空欄下書きの帰属を確認する方法が必要。これらを推測で埋めない。一般商品のCREATE最終クリックは引き続き封鎖し、将来その直前には同じ店舗の30秒送信gateを必須にする。

## 下書き詳細の読取専用collector

`generalPrivateCreateDraftCollector.mjs` は、下書き一覧の行を一つずつ開き、詳細URLの `productDraftId` と `name` / `variants.0.skuCode` を2回読む独立部品である。空欄行も省略せず、一覧の行数を呼び出し側が明示する。現時点の観測数は12件。全行を2周し、同じ行番号から同じID・商品名・管理コードが再読取できた場合だけ `DRAFT_DETAILS_DOM_OBSERVED` を返す。件数、行内容、URL、読み込み表示、ページネーション、重複ID、詳細入力のいずれかが曖昧なら結果を破棄する。返り値は常に `allowFinalCreate: false`。

実画面では、下書き表の安定後に12個の `<tbody><tr>` があり、行内に `<a>` やボタンはない。行そのものをクリックすると、非空欄の一行も空欄の二行も `/products/create?productDraftId=...` へ移った。空欄の詳細では商品名と管理コードの双方が空で、管理コードの入力名は `variants.0.skuCode` だった。詳細から一覧に戻った直後、一時的に13行、その後12行となる挙動も観測した。一覧に `aria-busy` / progressbar は観測されていないため、読み込み完了を単一スナップショットや行数だけで判断できない。

この部品はまだ実ブラウザーや出品前判定に接続していない。URLとDOMの安定だけでは、読取通信の応答がその下書きIDに対応した証明にならない。GraphQLの読取operation名も未観測であり、返す行は既存判定器の `detailVerified` 行ではない。読み取れない空欄行は未帰属として扱い、重複なしの証明に使わない。部品内にフォーム入力・保存・新規作成の操作はない。

## 通常画面だけの重複調査候補（2026-10-08）

`generalPrivateCreateNormalUiScan.mjs` は通信の経路設定や捕捉を使わず、ログイン済みの通常Shops画面で読取操作だけを行う独立候補である。2026-10-08の通常画面で、出品中一覧の `button[data-testid="product-status-chip"]` に `ステータス: 出品中`、`button[data-testid="visibility-chip"]` に `公開状態: すべて` が表示されることを確認した。既定のブラウザー読取器は両方がそれぞれ一つだけ存在し、文字列が完全一致した場合だけ50行以内の表・前後ボタン・URLを3回連続で安定確認する。`在庫: すべて` や別項目の「すべて」選択は代用しない。次ページへのクリック後は、旧ページと異なる行集合が3回安定するまで待つ。遷移中の51行や両ボタン無効を終端と扱わない。最初のページで前後ボタンが両方無効でも終端証拠としない。50ページの上限、表示変化なし、フィルター不明、読取失敗は固定の未確認状態で止まる。

出品中の画面上の商品名と、上記下書きcollectorで読んだ商品名・管理コードだけを比較する。一致を見つけた場合は `REMOTE_DUPLICATE_POSSIBLE` とし、商品情報は出力しない。出品中の管理コードを全行で確認するUI契約は未観測のため、一致が見えなくても `REMOTE_SCAN_INCOMPLETE / SALE_SKU_UNVERIFIED` とする。結果は常に `allowFinalCreate: false`。通常画面の通信本文、URL、商品ID、商品名、管理コードを記録・表示しない。保存・新規作成・公開ボタンやフォーム入力は呼ばない。この候補も独立レビュー前に実画面では使わない。

2026-10-08に通常の専用ブラウザーで対象1件だけ読取を試したところ、結果は `REMOTE_SCAN_INCOMPLETE / SALE_TABLE_UNVERIFIED` で、詳細行に進まず終了した。区別できなかった原因を固定コードだけで切り分ける次候補では、認証画面・URL、出品中ステータス、公開状態、表、51行以上の一時表示、ページボタンの個数・状態、行集合の未変化を別々に返す。画面文章、タイトル、管理コード、商品ID、URL値、通信本文は返さない。候補の独立レビュー後まで同じ実画面で再実行しない。
