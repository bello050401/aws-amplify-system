## 途中で起きた障害と、その根本原因

インスタンスを作っても中継が一切起動せず、ログもリスナーも残らない状態が続いた。
推測で作り直さず、使い捨てインスタンスで1変数ずつ切り分けた:

| user-data | 結果 |
|---|---|
| 3行の最小スクリプト | 実行される |
| 同じ内容を7,617バイトへ水増し | 実行される（サイズは無関係） |
| `set -uo pipefail` を足しただけ | **実行されない** |
| `exec >> log 2>&1` を足しただけ | 実行される |

**根本原因**: このLightsailイメージの cloud-init は user-data を **sh(dash)で実行し、
`#!/bin/bash` のシェバンを無視する**。dash に `pipefail` は無いため、`set -o pipefail`
の行でシェルごと終了する。ログ出力の設定より前に死ぬので、痕跡が何も残らなかった。

**対処**: user-data を POSIX sh 互換で書き、シェルオプションに頼らず各手順を明示的に
検査する。`dash -n` で構文を確認。再発防止として、構築スクリプトが送信前に
`set -e/-u/-o pipefail` と非ASCII文字を検出して失敗するガードを入れた。
外部依存も削った（NodeSource をやめ、Ubuntu標準の nodejs を使う）。

原因特定のために user-data へ一時的な診断サーバーを組み込んだが、
**検証で停止を確認済み**（下表「一時診断サーバーは停止している」）。

## 検証結果

### 外形検証 `scripts/aws-setup/12-verify-mercari-relay.ps1` — 24 passed / 0 failed

- 固定IP `13.196.230.130` が維持され、インスタンスへアタッチされている
- 一時診断サーバーは停止している
- 自前CAでTLS検証が通り `/healthz` が200 / 公開CAのみでは拒否される
- 正しい署名は通過。鍵違い・署名改竄・ヘッダ欠落はいずれも401
- 中継の認証失敗には `X-Bello-Relay-Error: AUTH` が付く（Mercariの401と区別できる）
- ±15分ずらしたタイムスタンプは401（リプレイ防止）
- 許可外パスは404 / 許可外メソッドは405 / URLらしき env は400（任意URLへ転送されない）
- 連投で429（19回目）
- ログにトークン・Authorization・共有鍵・本文のいずれも出ていない
- 再起動後、サービスが自動で復帰した
- 22番はLightsailブラウザSSHのみ（0.0.0.0/0ではない）。443と22以外は開いていない

### BELLO(Staging) → 中継 → Mercari の実測

Stagingの設定画面「EC出品（Mercari）」→「接続確認」を実行した。

| 条件 | 結果 | 意味 |
|---|---|---|
| 通常 | HTTP 404 / `IP_NOT_ALLOWED`（1.1〜1.5秒） | Mercariまで到達している。404はIP未申請による正常な応答 |
| こちらから中継のレート枠を空にした状態で実行 | `relay RATE, HTTP 429` | **Stagingのリクエストが中継を通っている証拠**。直接Mercariへ行っていれば、こちらの負荷とは無関係に404のままになる |
| 枠を空にするのをやめて再実行 | HTTP 404 / `IP_NOT_ALLOWED` | 元に戻る |

429のときの画面表示:

> Mercari Shops APIへの接続に失敗しました: リクエストが多すぎます。しばらく待って再試行してください。
> (Mercari中継サーバーでエラーが発生しました (relay RATE, HTTP 429)。**Mercariのトークンの正否は判定できていません**。)

保存済みTOKENは「設定済み（未検証）」のまま維持された。中継側の障害で
正しいTOKENが破棄されないことが、Staging実機でも確認できている。

### 経路の障害をMercariの障害と取り違えない

中継URLを死んだポートへ向ける対照実験を行ったところ、当初は
「Mercari Shops APIからの応答が時間内に返りませんでした」と表示された。
実際にはMercariまで届いていないので、この文言だと調査先を間違える。
中継が設定されているときは「中継サーバーへ到達できませんでした / TOKENの正否は
判定できていません」と書き分けるよう修正し、テストで固定した。
ログにも `via: "relay" | "direct"` を残す。

## 依頼事項（私からは実行できません）

Mercari Shops のAPI利用申請で、**送信元固定IPアドレス `13.196.230.130`** を
登録してください。Mercariは環境ごとに登録が必要なため、
**sandbox と production の両方**での登録が要ります。

登録が完了したら教えてください。設定画面の「接続確認」を実行して、
404が解消することを実測で確認します。

## 復旧・再構築

`scripts/aws-setup/12-create-mercari-relay.ps1` は冪等。インスタンスが壊れた場合、
再実行すれば同じ構成が再現される。**静的IPは独立したリソース**なので、
インスタンスを作り直しても `13.196.230.130` は変わらない（Mercariへの再申請は不要）。
