# 取引先向け商品カタログ

管理者は在庫一覧の「取引先に共有」から `/inventory/share` を開き、共有リンクを作成します。リンクを持つ方はログインせずに写真・商品名・管理番号・数量・寸法・作業段階を閲覧できます。有効期間は標準90日です。「リンクを更新」は旧リンクを失効させ、新しいリンクを発行します。「共有を停止」で閲覧を終了できます。

## 対象と公開範囲

- 有効なカテゴリの名称が「補修待ち」「撮影待ち」「出品待ち」と完全一致し、数量が正の整数の商品だけです。売却・削除・合算・出庫済み情報がある商品は除外します。工程が複数ある場合は補修→撮影→出品待ちの順で1区分に表示します。
- 保留、業者間、五十嵐などの会計集計用の別名をこのカタログには流用しません。
- 原価、価格、仕入先、顧客、社内メモ、保管場所、管理ページへのリンクは公開しません。商品名の先頭の管理用括弧は除去します。商品名そのものには公開できる内容を登録してください。
- 寸法の欠損は補完せず「—」、写真の欠損は「写真準備中」です。写真は既存在庫に紐づくNORMAL画像を参照し、複製しません。

## 更新とアクセス制御

公開APIは `/api/shared-inventory/[token]`、画像はその配下の `/image/[id]?index=N` です。256bitのランダムリンクを、期限・停止状態・現在のトークンハッシュで認可します。一般の在庫APIを匿名に開放しません。管理APIは独立に検証したADMINセッションと同一Originを必須とします。

対象候補IDだけを最大15秒キャッシュします。毎回現在の在庫とカテゴリを強整合読み取りし、売却・対象外化を再確認します。画面には最終確認日時と更新ボタンがあります。開いたままの画面は自動更新しません。新規対象の追加は候補更新後に表示されます。

画像は同じリンク認可と現時点の商品適格性を確認して既存S3から中継します。任意URLや任意S3キーは受け付けません。JSON・画像・共有ページはno-store/no-referrer/noindexです。Next画像最適化キャッシュによる失効後の再配信を避けるため、通常のimg要素を使います。

## 保存とロールバック

既存InventoryAnalysisMetadataの`scope=control`に`partner-catalog:grant:*`と`partner-catalog:token:*`を保存します。原在庫・EC・価格の変更はありません。再発行と停止は条件付きPutのトランザクションで行い、旧トークン参照は無効な墓標に置き換えます。既存のIAM許可とDBスキーマを変更しません。

停止はまず管理画面でリンクを無効化します。コードを戻す場合は今回追加の共有ページ/API/管理ページ/ツールバー入口と専用ヘッダーだけを戻します。メタデータを削除する必要はありません。直前リリースへ戻した後は共有URLが存在しなくなり、元の在庫機能が継続します。
