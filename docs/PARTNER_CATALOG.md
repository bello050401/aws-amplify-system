# 取引先向け商品カタログ

管理者は在庫一覧の「取引先に共有」から `/inventory/share` を開き、共有リンクを作成します。iPhoneホームの「社外共有」と管理画面で、リンクごとに公開する商品を選び「選択を保存」します。リンクを持つ方はログインせずに写真・商品名・管理番号・数量・寸法・作業段階を閲覧できます。有効期間は標準90日です。「リンクを更新」は旧リンクを失効させ、新しいリンクを発行します。「共有を停止」で閲覧を終了できます。

## 対象と公開範囲

- 管理者がそのリンクに明示的に選択した商品だけを公開します。新規・旧リンクとも選択未保存は0件です。対象商品が増えても自動追加しません。上限500件、選択解除は次の一覧取得・画像取得から反映します。
- 有効なカテゴリの名称が「補修待ち」「撮影待ち」「出品待ち」と完全一致し、数量が正の整数の商品だけです。売却・削除・合算・出庫済み情報がある商品は除外します。工程が複数ある場合は補修→撮影→出品待ちの順で1区分に表示します。
- 保留、業者間、五十嵐などの会計集計用の別名をこのカタログには流用しません。
- 原価、価格、仕入先、顧客、社内メモ、保管場所、管理ページへのリンクは公開しません。商品名の先頭の管理用括弧は除去します。商品名そのものには公開できる内容を登録してください。
- 寸法の欠損は補完せず「—」、写真の欠損は「写真準備中」です。写真は既存在庫に紐づくNORMAL画像を参照し、複製しません。

## 更新とアクセス制御

公開APIは `/api/shared-inventory/[token]`、画像はその配下の `/image/[id]?index=N` です。256bitのランダムリンクを、期限・停止状態・現在のトークンハッシュで認可します。一般の在庫APIを匿名に開放しません。管理APIは独立に検証したADMINセッションを必須とします。Webは同一Origin、既存のネイティブアプリは署名検証されるCognitoセッションCookieを利用します。OriginなしはX-Bello-Mobile:1かつブラウザのFetch Metadataなしの場合だけ受け付け、異なるOrigin・cross-siteは拒否します。

管理画面の対象候補IDだけを最大15秒キャッシュします。毎回現在の在庫とカテゴリを強整合読み取りし、売却・対象外化を再確認します。画面には最終確認日時と更新ボタンがあります。開いたままの画面は自動更新しません。新規対象は候補更新後に選択でき、保存後に公開されます。公開読み取りは選択IDだけを強整合で再取得します。

画像は同じリンク認可・現在の選択ID・現時点の商品適格性を確認して既存S3から中継します。一覧は既存の軽量画像、拡大時だけ`size=full`でその写真の原本を取得します。任意URLや任意S3キーは受け付けません。JSON・画像・共有ページはno-store/no-referrer/noindexです。Next画像最適化キャッシュによる失効後の再配信を避けるため、通常のimg要素を使います。

## 保存とロールバック

既存InventoryAnalysisMetadataの`scope=control`に`partner-catalog:grant:*`と`partner-catalog:token:*`を保存します。原在庫・EC・価格の変更はありません。再発行と停止は条件付きPutのトランザクションで行い、旧トークン参照は無効な墓標に置き換えます。既存のIAM許可とDBスキーマを変更しません。選択IDは同じgrant行のselectedIdsへ保存し、revisionの条件付きPutで競合を409として拒否します。選択保存でURL・トークン・有効期限は変わりません。

管理API: GET `/api/inventory/partner-catalog/selection?id=GRANT_ID` は現在のgrant、公開項目だけの候補DTO、上限を返します。POST同URLへ `{id, revision, selectedIds}` を送ると適格性を再確認して保存します。候補の画像はADMIN専用 `/api/inventory/partner-catalog/image/ITEM_ID?index=N` で軽量画像のみ取得します。未選択商品の公開画像URLは利用できません。JSON・画像ともデータ取得後に認可を再確認し、選択解除・停止・期限切れが途中で起きた応答を拒否します。

停止は管理画面でリンクを無効化します。今回の選択制限を取り除くロールバックでは、以前の版も共有URLを持ち、全対象商品を公開するため、稼働中のリンクをそのまま残すと公開範囲が広がります。選択制限を取り除く前に、該当する有効な共有リンクをすべて停止し、公開一覧APIと画像APIがともに404を返すことを確認してください。共有を継続する場合は、選択未保存を0件とする制限と画像の選択ID認可を残した版へ戻します。メタデータは削除せず、停止状態と選択IDを保持します。
