対象ブランチ: `claude/inventory-management-system-5vbvc7`

## 1. Bedrock の再調査 — 前提を捨てて実測しなおした

前回「Anthropic の利用目的フォーム提出が必要」と報告したが、これは
**Anthropic モデルに限った話**であり、AI Vision に必要な条件ではなかった。
利用者に AWS 操作を依頼した件は撤回した。

実測（us-west-2、既存の AdministratorAccess + SSO セッション）:

| 確認項目 | 実測結果 |
|---|---|
| 画像入力に対応するモデル | Anthropic 以外に **27 件**（Amazon 8 / OpenAI 3 / Mistral 6 / Google 3 / Meta 2 ほか） |
| `amazon.nova-lite-v1:0` | フォーム提出なしで応答 |
| `us.amazon.nova-lite-v1:0` | フォーム提出なしで応答 |
| `us.amazon.nova-pro-v1:0` | フォーム提出なしで応答 |
| Anthropic 各モデル | `404 Model use case details have not been submitted` |

結論: **利用者の操作は 1 つも必要ない。** 既定モデルを
`us.amazon.nova-lite-v1:0` とした。Anthropic が使えるようになれば、
同じ `VisionAnalyzer` を実装したクラスを足すだけで差し替えられる。

## 3. AI は難例だけに使う

参照写真 4 枚では **AI を 1 回も呼ばなかった（0/4）**。露出補正を被写体検出の
前へ動かした時点で、ローカル解析の確信度が足りているためで、これが正しい
挙動である（仕様 §5「全画像に無条件で AI を適用する設計は禁止」）。

経路そのものが未検証のまま出荷されないよう、仕様が難例として名指ししている
white-on-white を合成し、`NO_LOCAL_SUBJECT` を実際に発火させて経路を通した。

## 4. テストが見つけた 2 つの実装欠陥

いずれも「AI の答えを信じすぎる」種類の欠陥で、テストを書いた結果として出た。

### 4.1 一致度に包含率を使っていた

ローカルと AI の bbox の一致を「小さい方に対する重なり率」で測っていた。
AI が **「画面全体が商品」** と答えると、ローカルの小さな bbox は完全に
含まれるので比率は 1.00 になり、**最も危険な応答が「完全に一致」と判定**
されて確信度が上がっていた。大きさの食い違いを罰する **IoU** に変更した。

### 4.2 ローカルが商品を見つけられないときに素通りしていた

`NO_LOCAL_SUBJECT` の経路は比較相手が無いため一致判定を飛ばし、AI の座標を
確信度 0.6 で採用していた。0.6 は `MIN_CROP_CONFIDENCE`(0.45) を超えるので、
全画面 bbox のまま crop へ進み得た。**比較できないときこそ答えの成立を見る
必要がある**ため、面積 0.7 以上の主張を `AI_BBOX_IMPLAUSIBLE` として却下し、
確信度を 0.4 まで落とす（＝構図を触らせない）ようにした。

E2E で確信度 0.60 → **0.00** に是正されたことを確認済み。

## 5. 周辺減光の入れすぎ（AI とは無関係の実害）

減光量は元画像の**全面**（中心 vs 四隅）で測るが、補正が掛かるのは
**crop した後の狭い範囲**で、そこに元の隅は含まれない。全面ぶんの持ち上げを
そのまま当てていたため入れすぎになっていた。

椅子の組の実測: 周辺減光 101 → **-46**（隅のほうが中心より明るい）、
**白飛び 8.0%**。お手本の残留減光は -11、白飛びは 0.0% である。

補正量に対する残留減光の応答は線形なので、0 と L0 の 2 点を crop 後の画で
実測して残留が 0 になる量を解き、さらに実際に白飛びが出ないところまで
下げるようにした（`solveVignetteLift`）。推定値ではなく測定値だけを使う。

## 8. 現時点で有効化していないこと

`amplify/functions/image-processing-worker/handler.ts` は
`new SharpImageProcessingProvider()` を引数なしで生成しており、
**デプロイ環境では AI Vision は一切呼ばれない**（`visionAnalyzer` は opt-in）。

有効化するには次の 3 つが要る:

1. worker で `{ visionAnalyzer: new BedrockVisionAnalyzer() }` を渡す
2. worker の実行ロールへ `bedrock:InvokeModel`（`us.amazon.nova-lite-v1:0`）を付与
3. Staging 実機で難例を 1 件通して確認する

3 を済ませずに 1 を入れると「未検証の経路を本番へ出す」ことになるため、
この 3 つは一緒に行う。
