# BASE非公開登録の検証（2026-09-28）

本人の最新指示により、BASEとネクストエンジンへのAPI送信・更新は出品機能の検証に限って許可された。ただし、今回は商品の公開を行わず、非公開状態で連携して確認する。公開切替の提供は非公開検証と安全確認の後に扱い、この変更では公開操作を実装・実行しない。

BASE公式APIの `POST /1/items/add` は `visible=0` が非表示、`visible=1` が表示で、未指定時の既定は表示である。`POST /1/items/edit` は既存商品の `visible` を更新できる。`GET /1/items/detail/:item_id` は現在の `visible` を返す。参照: https://docs.thebase.in/api/items/add/ 、https://docs.thebase.in/api/items/edit/ 、https://docs.thebase.in/api/items/detail/

BELLOの従来実装は新規BASE登録時に `visible=1` を送っていたため、専用の非公開検証経路では `visible=0` を明示する。登録後は返された商品IDで公開状態を読み返す。もし表示状態なら直ちに `visible=0` の更新を試し、再度読み返す。確認不能や公開状態が残る場合は成功扱いにせず、返された商品IDとエラーをBELLOに残して重複登録を防ぐ。BASE商品IDが既にある場合、新規登録は拒否する。

非公開検証の書き込み許可は `BASE_PRIVATE_TEST_WRITES_ENABLED=1` のときだけで、新規登録の `visible=0` と既存商品を非公開に戻す `visible=0` 更新だけに限定する。既存の `EXTERNAL_WRITES_ENABLED` は変更せず、価格自動更新や公開への変更を同時に解放しない。合成検証と型検査は成功。実ショップAPIでの登録・非公開確認、検証環境への反映は未完了。

登録処理の結果が不明な場合に同じ商品を二重登録しないため、処理中またはエラーの記録が残る商品は再送信を止める。BASEが商品IDを返した後で公開状態を確認できない場合もIDを保持し、BASE管理画面の確認が必要なエラーにする。検証許可が未設定の場合は記録を処理中へ変える前に止める。

ネクストエンジンの商品のマスタ登録とメルカリShopsの公開設定は別物。ネクストエンジン商品マスタの登録成功だけで販売先の非公開が保証されたとは扱わず、販売先の実画面で非公開を確認するまで出品操作を進めない。
