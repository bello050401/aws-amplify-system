# BELLO WebからのメルカリShops出品: HTTP境界（2026-10-08）

## 実測と未実測

- 既存商品B005795の通常管理画面読取で得たGraphQL queryを、同じPCのログイン済みコンテキストから一度HTTP送信し、同じ商品・店舗の読取結果をHTTP 200で確認した。BELLO Webサーバーからの認証付き送信ではない。詳細は[認証付きHTTP読取検証](mercari-direct-read-proof-20261004.md)。
- 下書き一覧 `productDrafts` と詳細 `GetProductDraft` の `POST https://mercari-shops.com/graphql` 読取は、PCの管理画面で対象IDと要求・応答を照合した。作成履歴や新規作成の証明ではない。詳細は[下書き読取観測](mercari-draft-read-metadata-observation-20261008.md)。
- B005396のHARでは `CreateProductDraft` が同じ名称・SKUで2回成功して別々の下書きを作り、`UpdateProductDraft` により一方だけ価格99,999円・画像1件へ更新された。画像アップロードの要求本文とBELLOサーバー用の認証方法は未確認。詳細は[限定観測](mercari-b005396-http-draft-har-evidence-20261009.md)。

## 今回実装したWeb側の工程

B005396のBELLO保存済み下書き・選択項目をサーバーで再読取し、配送条件の確認後、商品ごとに一件の `MercariBridgeHttpDraftJob` を条件付きで記録する。内容とSHA-256指紋は固定し、同じ内容の再クリックは同じ依頼に収束させる。異なる内容は競合として停止する。状態は `AWAITING_HTTP_AUTH_AND_CREATE_CONTRACT`。この操作はShopsへ通信せず、PCランタイムも起動しない。B005396のWeb画面からPCへの引渡しボタンは外した。既存のBASEとNext Engineの動作は変更していない。

EC出品画面では、既存のメルカリShops欄の直下に「HTTP方式での出品」欄を置いた。「HTTP方式で出品を指示（準備登録）」は上記のWeb依頼だけを記録する。依頼状態はサーバーから再読取して表示し、Shopsの結果は「未送信（出品成立は未確認）」と明示する。従来のPC準備欄は別の欄として維持する。

2026-10-09に通常商品にも同じHTTP準備欄を広げた。商品ごとに店舗IDと在庫UUIDから固定した依頼IDを使い、BELLO保存内容を二回読み、商品名・説明・状態・画像参照・下書き更新日時・数量・カテゴリーを照合する。同じ商品で異なる内容を登録し直そうとした場合は競合で止める。既存Shops商品B005795/B005757と過去テストB005659/B005413は新規作成依頼の対象外。B005396の価格99,999円・数量1の特別条件は維持する。

Web HTTP実行ゲートは、準備ジョブのID・スナップショット指紋を検証して初期状態を作る純粋な状態遷移として置いた。新規送信を許すには、認証有効、書込契約確認済み、既存紐付けなし、Shops側重複なし、店舗全体の直近送信履歴を取得済み、最後の送信から30秒以上が必要。認証切れは停止し、送信開始後の認証切れ・結果不明は確認待ちのまま同一依頼を再送しない。このゲートは現時点でHTTP送信を起動しない。将来の実行器には、送信前の最新照合と送信開始記録を原子的に永続化することが必要。

送信開始予約の永続化候補を追加した。店舗ごとのスロット条件更新と依頼IDごとの一回限り試行作成をDynamoDBの単一トランザクションで確定する。予約から4秒以内に送信を開始する期限を持たせ、次の商品は5秒の予約期間とさらに30秒が過ぎてから予約できる。トランザクションの応答遅延で期限を過ぎた場合や確定結果が不明な場合は送信可能と判定しない。送信器を接続する際はHTTP呼出し直前にも期限を確認する必要がある。予約関数は有効な認証と「本人再認証を確認済み」の入力を必要とするが、その確認値を得るサーバー側の認証処理は未接続。テーブル名・実行ロールの権限設定とShopsへの送信器も未接続。

## Webからの出品を完了する条件

公式API経路には、この店舗のBELLO用Personal API Access Token、API_CLIENT_NAME、承認済みの日本国内固定送信元IPが必要とされるが、利用可能な設定は未確認。通常の管理画面ログインやNext Engine用トークンはその代わりにならない。公式APIの `createProduct` 入力にはHTTPS画像URLが必要であり、BELLO保存画像をその方式で安全に渡す準備も要る。これらを確認し、読取実証・非公開作成・同じSKU/商品IDの読戻しをつないで初めてWeb出品を完了と判定する。内部の管理画面GraphQLは下書き作成・更新の通信を観測したが、BELLOサーバーで使える認証と画像アップロード要求本文が不明である。同じ名称・SKUの二重作成も実際に起きたため、既存IDと固定ジョブの照合ができるまで新規作成を再送しない。
