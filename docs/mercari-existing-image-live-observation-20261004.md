## 保存前に確認した経路と観測上限

旧「既存商品を非公開で1回保存」の永久マーカーによりPCアプリの保存ボタンは無効で、保持中の画像セッションを渡す保存処理もない。再実行やマーカー解除はしない。この時点で残っていた経路は、本人が同じChrome画面で「公開設定に進む」から**「非公開で保存する」**を1回だけ押す操作だった。公開ボタンは押さない。

画像セッションに付けた通信観測器は、同一編集URL上で発生したPOST/PUT/PATCHのfetch/XHRを最大20件まで観測する。保存前は6件だったが、画面遷移、対象URLの変化、件数上限などで保存送信を捕捉できない場合がある。GraphQLのJSON応答なら、安全な操作名・応答直下キー・`errors`有無を表示し、既知の`createProduct`/`updateProduct`/`product`形状の応答だけで既存商品ID・店舗IDとの一致と既知の公開状態を比較できる。未知形状やmultipartはID・状態が未観測のまま。HTTP 200だけで保存成功にしない。

保存が不明な段階で同じ専用Chromeをリロード・終了すると、未保存の画像関連付けを失う可能性がある。そのため、このChromeは保持したまま、別セッションでの保存後読戻しを選んだ。

## 現在セッションの読取境界

稼働中PCアプリは同じPlaywright `page`を保持しているが、公開するローカル操作は通信概要更新だけ。画像一覧を再読取する操作はない。保存後のコード差し替えも稼働中のNodeプロセスには反映されない。ブラウザー操作ツールに当該Chromeのタブは表示されず、Windows Computer Useは対象URLを安全に特定できず読取前に停止した。同じプロフィールを別プロセスで開かず、現在のセッションを閉じず、画像選択を繰り返さない。

作業ブランチの次版コードには、保持中の同じ `page` に限り、対象の正確な編集URLと商品管理コード等を再照合して、既存の `readExistingUploadedImages` で画像の枚数・元画像のパスハッシュを読む専用ボタンを追加した。表示は固定の結果コードだけで、URLや画像自体は表示・保存しない。合成テストは通過し、Astra独立レビューで新たなP1/P2指摘なし。ただし設置済みの稼働プロセスには反映しておらず、今回の保持画面へ後付けしていない。
