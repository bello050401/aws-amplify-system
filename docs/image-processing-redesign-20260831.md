# 画像自動加工の再設計（2026-08-31）

ユーザーから提供された4組の Before / After を教師として、商品写真の自動加工を
設計から作り直した記録。読みやすい版は Artifact
「BELLO 写真加工の再設計」にある（実際の画像を並べたもの）。

対象ブランチ: `claude/inventory-management-system-5vbvc7`
`engineVersion` 1 → 2（冪等キーに含まれるため、version 1 の既存結果は再加工対象）

---

## 1. 従来実装の監査（仕様書 §24）

推測ではなくコードで確認した。旧 `sharpProcessor.ts` が行っていたのは3つだけ。

| 処理 | 実態 |
|---|---|
| `rotate()` | EXIF orientation の正規化（正しい） |
| `resize({ fit: "contain", background: 白 })` | 目標比率へ**白帯を足す**。16:9 → 1:1 で家具は**相対的に小さくなる** |
| トーン補正 | 既定が `DEFAULT_ADJUSTMENTS`（コード自身のコメントに「恒等変換」）。worker は `adjustments: {}` しか渡さない → **明るさ・WB・彩度は一度も動かない** |

被写体検出・クロップは存在しなかった。したがって、提示された Before/After が
求める変化は**構造的に1つも起こり得なかった**。

## 2. Before / After の実測（仕様書 §2, §36）

解析は 640px へ縮小した RAW に対して行った。

| 組 | 占有率 | 背景輝度 | 周辺減光 |
|---|---|---|---|
| 椅子 | 3.1% → 6.4% | 166 → 214 | 101 → -11 |
| ピンクチェア | 5.2% → 12.6% | 134 → 195 | 110 → 21 |
| 水色ソファ | 4.3% → 16.3% | 120 → 185 | 74 → -16 |
| 丸テーブル | 0.9% → 7.9% | 51 → 209 | 52 → -8 |

加えて、Before はいずれも青チャンネルが突出（紫かぶり）しており、
丸テーブルの After は右端のスタジオ機材を crop で完全に除外していた。

**出力比率は 1:1 固定ではない。** 椅子と丸テーブルは 1080×1080（1:1）、
ピンクチェアと水色ソファは 1024×768（4:3）だった。人間は横長の商品を
正方形へ押し込んでいない（仕様 §8 と一致）。

## 3. 構成（仕様書 §40 責務分離）

| ファイル | 役割 |
|---|---|
| `lib/imageProcessing/analysis.ts` | 被写体と背景の測定。**ピクセルを1つも生成しない**。sharp 非依存の純粋関数 |
| `lib/imageProcessing/cropPlanner.ts` | 構図の決定。切らない・canvas を広げない・確信度が低ければ触らない |
| `lib/imageProcessing/toneMap.ts` | 露出 / WB / 周辺減光の決定。商品色を動かさない上限つき |
| `lib/imageProcessing/sharpProcessor.ts` | 上記の決定を1回のピクセル走査で適用し、派生画像を生成 |

出力は元画像に存在する画素の crop・リサイズ・色調補正だけで作る。
欠損の補完、傷の除去、背景の差し替え、形状の変更は行わない（仕様 §1.1）。

## 4. 実画像で合わせ込んで判明した問題

コードを読むだけでは気づけず、出力を測って初めて分かったもの。
いずれも修正箇所にコメントとして残してある。

### 4.1 周辺減光は「元フレームの座標」で補正する

切り出し後のフレーム中心を基準にすると、実際には減光していない中央付近まで
持ち上げる。**白飛び率 39〜63%** を観測した。
`applyTonePixels` は `sourceRect` を受け取り、出力画素を元フレームの
正規化座標へ写してから半径を求める。

### 4.2 ゲインは減光補正の「後」に決める

補正前の（暗い隅を含んだ）背景輝度からゲインを計算すると二重に持ち上がる。
**背景が 249〜255 まで飛んだ。** 解析用の縮小画像へ減光補正だけを当てて
crop し、その状態で測り直してからゲインを決める2段階にした。

### 4.3 ゲインの上限はハイライトの余地で決める

背景輝度だけを見ると、極端に暗い写真（背景51）でゲインが 3.03 になり、
背景が 254、白飛び 62% になった。
画像全体の輝度95パーセンタイルが 245 を超えない範囲へ制限する。

### 4.4 切り口は4辺を別々に評価する

4辺の平均を取ると、1辺だけが商品を横切っていても残り3辺の背景（実測0.00）で
薄まる。**左辺 0.04 が全体平均 0.01 になり**、ピンクチェアの白いテーブルを
切る構図がそのまま通っていた。`borderLikelihood` は辺ごとの平均の最大値を返す。

### 4.5 白い床の上の白い天板は輪郭でしか見つからない

明るさでも彩度でも背景と区別がつかない（尤度 0.04）。数画素で大きく変化する
勾配を重みに加えて、ようやく商品の一部として拾えるようになった。

| 組 | 出力 | 占有率 | 背景輝度 | 白飛び |
|---|---|---|---|---|
| 椅子 | 743×744 / 1:1 | 3.9 → 8.6%（理想8.1） | 166 → 220（理想214） | 8.0% |
| ピンクチェア | 981×654 / 3:2 | 6.2 → 13.3%（理想14.3） | 134 → 190（理想195） | 0.1% |
| 水色ソファ | 959×960 / 1:1 | 9.1 → 10.9%（理想25.5） | 120 → 186（理想185） | 0.0% |
| 丸テーブル | 構図変更なし | 2.3 → 3.8%（理想9.9） | 51 → 122（理想209） | 0.0% |

商品の色味ずれは 1.0〜2.2pt で、いずれも許容内（明るさは変わるが色相は保持）。
1枚あたり 0.74〜0.91 秒。

参照画像はユーザーの実商品写真なのでリポジトリへ入れていない。既定の場所が
無い環境では `BELLO_BENCHMARK_DIR` で指定でき、見つからなければ
失敗ではなくスキップする。`BELLO_BENCHMARK_OUT` を指定すると加工結果を
書き出して目視できる。

## 6. 未達（NOT_ACHIEVED）

**丸テーブルの機材の写り込みは除外できていない。**

元画像が暗く（背景輝度51）、床のスポット光が商品と同じ強さで検出されるため、
bbox 内部の平均尤度が 0.14 を下回り確信度が閾値未満になる。
`LOW_CONFIDENCE` として自動での構図変更を見送り、元の構図のまま明るさだけを
補正している。仕様 §2.4 が求める「右の機材を crop で除外」は達成していない。

切り間違えるより触らない方を選んだ結果であり、`CropPlan.reason` に理由が
残るので UI から説明できる。

## 7. テスト

`scripts/verify-image-processing.ts` は 60 → 87 件。

「SQUARE_1_1 指定なら常に正方形（contain で余白を足す）」を固定していた既存
テストは、**今回の仕様が禁じている挙動を検証していた**ため、削除ではなく
新しい要求を検証する形へ書き換えた。追加したのは主に:

- 被写体のある合成画像で、白帯を足さず crop で比率を作ること
- crop 矩形が被写体を完全に含むこと（4辺すべて）
- crop 後に被写体が画面に対して大きくなること
- DAMAGE 画像は元構図を保つこと
- 暗い画像が明るくなるが白へ張り付かないこと
- WB 補正に上限があること

全10スイート 503件合格、typecheck / lint / build 通過。
