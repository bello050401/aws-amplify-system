# メルカリShops画像プレビューの候補修正（2026-10-06）

## 観測

B005757の既存商品編集画面では、画像追加の見えるタイル `data-testid="image_box"` を押すとファイル選択が開いた。ファイル選択後、既存画像は完成済みの HTTPS `img[alt="uploaded-image"]`、新しい未保存プレビューは完成済みの `data:` `img[alt="uploaded-image"]` になった。旧コードは両方を HTTPS 画像として要求したため、30秒待っても2枚目を検出できない。画像資産作成の HTTP 200 は商品への関連付けや非公開保存を証明しない。

BELLOのB005757には出品画像が1枚、在庫の追加アップロード画像もトップ画像が1枚だけ保存されている。今回選択した画像は既存商品画像と同じ見た目だった。未保存の重複プレビューはShops画面から除去され、元画像1枚へ戻った。元の画像選択と復旧の2つの `UNKNOWN` claimは残し、再実行しない。

## 候補の動作

- 画像バイトとSHA-256を事前に固定し、既存商品・非公開状態・元画像1枚・ファイル入力を照合する。claimを書いた後、同じく確認済みの唯一の `input[type=file]` に固定バイトを1回渡す。実機の2回の試行では、この入力で画像資産作成HTTP応答が観測されており、問題は後続のHTTPS専用プレビュー検出にあった可能性が高い。見えるタイルからファイル選択を開く方式は、無関係なファイル選択イベントを拾う競合があるため採用しない。
- 未保存プレビューはブラウザー内で `data:` の画像バイトをSHA-256にし、BELLO画像と完全一致する場合だけ `PENDING_PREVIEW_OBSERVED` と記録する。URLや画像バイトは結果に出さない。
- `data:` プレビューは保存済みの画像資産として扱わない。商品項目と元画像、プレビューのバイト一致を再確認した後、保存claimを先に書く。見える「公開設定に進む」を押し、同じプレビューをもう一度確かめてから「非公開で保存する」だけを1回押す。モーダルを開いただけでは保存済みと扱わない。
- 保存応答を対象商品・非公開状態まで照合できた場合だけ編集画面を再読込し、元画像と別のリモートHTTPS画像の2枚を確認する。さらに別タブで同じ商品・非公開状態・同じ2枚を読み直す。これでも選択画像とリモート資産IDの結合は未証明なので、`PRIVATE_TWO_IMAGES_ATTRIBUTION_UNVERIFIED` / `UNKNOWN` として保持する。保存応答が未確認でも別タブの読取は試すが、結果は `UNKNOWN` のままにする。

## 残る条件

プレビューのバイト一致だけでは、その画像資産IDが対象商品へ関連付けられたことを証明できない。現行の通信観測器は画像資産IDを保持せず、画像資産作成応答と保存要求の対応も検証できない。したがってこの経路は非公開保存を一度だけ**試行**できるが、選択画像の出品完了には昇格させない。実サイトの認証済み保存要求の契約もまだ実証されていないため、応答が不明なら `UNKNOWN` のままにする。

実機の一連試験には、B005757とは別の、利用者が指定した在庫・既存非公開Shops商品・販売価格・既存写真とは異なるBELLO写真が必要。対象のIDと画像ハッシュを固定し、旧claimがないことを確かめ、独立レビュー後に一回限り実行する。今回のB005757と保持中のPC/Chromeには候補コードを入れない。
