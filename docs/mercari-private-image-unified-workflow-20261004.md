# 既存商品への画像追加・非公開保存を1操作で確認する次版設計

2026-10-04時点の作業ブランチ実装。**設置済みPCアプリには反映しておらず、B005795では実行しない。** B005795の既存画像選択と非公開保存はそれぞれ試行済みであり、旧マーカーを解除・再利用しない。現行の専用ChromeとPCアプリは終了・再起動しない。

## 操作と停止条件

管理者が別の未試行の既存非公開商品を選び、BELLOから取得した1枚の画像を固定した設定で `imageWorkflowEnabled: true` を明示すると、PC画面は従来の画像選択・保存の個別ボタンを隠し、「画像1枚を追加して非公開保存・確認」だけを表示する。1回の操作中は画面が段階を2秒ごとに更新し、他の操作を受け付けない。

1. 旧画像試行・旧保存試行・新工程のいずれかのマーカーがあれば、Shopsを開く前に停止する。認証切れや対象URLの相違も画像選択前に停止する。
2. 正確な既存商品IDの編集画面で、商品コード・価格・数量と非公開一覧の相関を確認する。既存画像が1枚であること、ファイル入力の形、BELLO画像のSHA-256とJPEG/PNG形式・容量を検証する。
3. 新工程専用の画像試行マーカーを耐久保存してから1枚をファイル選択する。元画像を保持したまま異なる2枚目が表示されるまで最大30秒待つ。対象商品と2枚の表示が一致しない場合は再送せず、Chromeを保持して `UNKNOWN` とする。
4. **別の非公開保存試行マーカー**を耐久保存し、同じ画面で「公開設定に進む」→「非公開で保存する」を1回だけ押す。直前にも商品コード・価格・数量を検証する。公開ボタン、新規商品作成、在庫変更は行わない。
5. 関係のない外部テレメトリーを除外し、Shops GraphQLだけを観測する。最終保存クリック直前に観測枠を切り替え、画像送信時の通信が20件に達していても保存要求を優先して記録する。要求の操作名・操作種別・query SHA-256・変数の項目と型・対象ID一致・非公開一致、および同じ要求へのHTTP/GraphQL応答の固定分類だけを残す。実際の保存要求の契約を別途検証して固定するまでは、応答形状だけで保存成功に昇格させない。契約を固定した後も、クリック後の契約一致要求に対する応答がHTTP 200、GraphQL `errors` なし、対象商品ID・店舗ID一致、状態が `UNOPENED` または `PRIVATE` のときだけ認める。
6. 応答を認めた場合だけ同じ商品編集画面を再読込し、商品コード・価格・数量、元画像と追加画像の2枚を照合する。非公開一覧の対象行から同じ商品IDへ戻り、再度2枚を確認して初めて `CONFIRMED_PRIVATE_WITH_IMAGE` を記録する。

認証切れ、クリック失敗、応答未確認、再読込不一致は停止する。応答未確認時には元の編集画面を保持し、別タブで対象商品・画像2枚・非公開状態の読取を試みる。この読取が成功しても保存要求は `UNKNOWN` のままで再送しない。画像選択後の未知結果では専用Chromeを閉じず、読取専用の画像表示確認と通信概要更新を画面に残す。記録した試行は再実行しない。結果コード・段階コード・読取結果・秘匿済み通信概要をローカルPCに保存する。画像本体、認証値、GraphQL本文や変数値は保存しない。

## 受入の範囲

合成テストは画像選択→保存→応答→再読込の順序、未知応答時のChrome保持と別タブ読取・再実行拒否、旧マーカーによるB005795停止、認証切れ、外部テレメトリー除外、保存要求候補の秘匿済み記録、PC画面の実行中表示を確認する。**Shops実サイトの保存要求と`updateProduct`応答形状は今回特定できていない**ため、現状の既定設定では成功判定できない。次の未試行商品を1回だけ非公開保存し、その操作で記録した要求候補を検証してから契約を固定する。対象の新しい実商品・画像・価格・数量が揃うまで実機の新工程は実行しない。
