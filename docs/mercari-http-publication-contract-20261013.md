## 今回のコード変更と検証

- 公開・停止・検証・商品読取のGraphQL文書を実要求から抽出。変数、認証情報、商品固有値はコードへ転記していない。
- 最新の商品読取から停止リクエストを組み立てる。商品と在庫のsnapshotId、数量、画像、カテゴリ末端、配送等を保持する。HARの変数をそのまま再送する実装ではない。
- 保存HARのEditProductPage応答を入力すると、生成した停止の全文が観測したUpdateProductV2要求とキー順序を除き完全一致。公開ACKと停止ACKも同一商品の結果として解釈できた。ネットワーク送信はしていない。
- 下書き読取のカテゴリを単一オブジェクトと扱う不具合を修正。実際は `categories[].category[]` の大分類→小分類の配列であり、最後のIDが入力のcategoryIdsに一致する。既存テストも誤った形を作っていた。過去HARの2件の下書き応答をオフラインで正常解釈し、末端カテゴリ一致を確認した。
- 既存の認証Cookieを受け取ってSelf→OwnShops→EditProductPageを読むサーバー専用入口を追加。IDP再ログインは行わない。秘密値は返さず、認証切れや判定不能は削除と解釈しない。Cookieの取得・保存・更新そのものは未接続。
- 関連18試験、TypeScript検査、差分空白検査を通過。試験ではネットワークを模擬した。`node --conditions=react-server --import tsx --test ...` で検査し、node_modulesは変更していない。
