# BELLO・ネクストエンジン・販路の役割（2026-10-02）

## 判断

BELLOを商品・写真・原価・実在庫・出品判断の正本とする。ネクストエンジン（NE）は**連携できる店舗の受注・販売可能数・出荷の運用拠点**とする。各販路の商品ページは店舗ごとに確認して公開する。全販路をNEだけで完結させる設計にはしない。

最大の理由は、現在のヤフオクがストアではないこと。NEはYahoo!オークションのストアに対応し、個人アカウントには対応しないと明記している。ラクマは公式ショップ化を目指すため、開設後はNE連携の対象とする。

## 販路別の扱い

| 販路 | NEとの関係 | 当面の運用 |
| --- | --- | --- |
| ヤフオク（非ストア） | 公式のNE自動連携対象外 | BELLOから出品内容を準備し、人がヤフオクへ登録・販売終了を反映。売れたらBELLOへ記録し、必要ならNEへ手入力またはCSVで受注を起票して配送作業を集約する。 |
| BASE | `BASE全自動`アプリは商品・在庫・受注・出荷を個別に設定できる | **商品ページ作成はBELLO→BASE APIを維持**。NEアプリの商品連携・画像連携・カテゴリ連携をオフにし、在庫・受注・発送連携だけ使う案を一件で検証する。 |
| メルカリShops | 連携アプリで商品連携、在庫・受注等に対応 | BELLOからNEへ商品マスタを準備。NE側の商品ページ・画像・アプリ新規出品を人が確認して開始。 |
| 楽天市場 | NEの受注・在庫・商品登録機能と相性がよい | 出店後にNE経由の運用を優先検討。 |
| 楽天ラクマ | NE連携アプリは**ラクマ公式ショップ**向け | 公式ショップ開設後、NE経由で出品・在庫・受注を扱う候補。 |

資料: [Yahoo!オークション](https://next-engine.net/manageable-systems/yahoo-auction/) / [BASE連携アプリの設定](https://basene-doc.s3-ap-northeast-1.amazonaws.com/manual/base_renkei_manual.pdf) / [メルカリShops連携アプリの操作マニュアル](https://mrs.ne-receiver.com/manual) / [楽天市場](https://next-engine.net/manageable-systems/rakuten/) / [ラクマ連携アプリ](https://base.next-engine.org/apps/4380/detail/)

## データの正本と変更の流れ

1. BELLOでSKUを一意に発行し、在庫・商品説明・写真・原価を管理する。
2. NEに連携する店舗では、同じSKUを紐付ける。店舗への販売可能数の配信と注文の集約はNEに任せる。BELLOとNEの実在庫差異は検知・解消する。
3. 商品名・価格・カテゴリ・配送条件・画像順・公開状態は販路ごとに異なるため、BELLOの共通下書きに販路別設定と確認状態を持つ。NE商品マスタを登録した事実を、各販路への出品完了として扱わない。
4. 一点ものを複数販路へ同時掲載する場合、非連携のヤフオクが残る限り売り越しリスクはゼロにならない。ヤフオクで売れたら即時にBELLOを販売済みにし、NEへ受注を手入力・CSV登録するか販売可能数を0にして他販路を止める。NE側で売れたらヤフオク出品を人が終了する。高リスク商品は同時掲載対象から外す運用も選べる。[NEの手入力・CSV受注](https://next-engine.net/functions/jyuchu/)
5. BASEの商品名・説明・価格・写真・公開はBELLOを編集元とし、NEアプリの商品連携は「利用しない」にする。NEを導入するなら在庫数の編集元だけはNEに切り替える。BELLOのBASE登録APIは現在 `stock` を送信し、更新APIも `stock` を送れるので、切替時に二重更新を止める実装修正が必要。
6. BASE連携アプリは商品連携を「利用しない」にしても在庫更新を使える設定がある。ただし、BASE商品コードとNE商品コードの一致、BASEの商品コードApp、NEの商品マスタ・モール商品一括登録が必要。BELLOの現行BASE登録APIは商品コード `identifier` を送らないため、連携開始前にSKUをBASEへ設定する修正と既存商品の照合が必要。[BASE連携アプリFAQ](https://basene.hm-net.co.jp/faq) / [BASE API](https://docs.thebase.in/api/items/add/)
7. NEの受注集約は、注文の確認、引当、出荷確定、追跡番号の返送を簡易化する。BASE注文はアプリ経由でNEの受注伝票に入り、出荷確定後にBASEへ通知される。送り状はNEの佐川e飛伝・ヤマトB2等との連携を利用できる。ただし、家具配送の手配まで自動化できるとは確認していない。[BASE連携アプリマニュアル](https://basene-doc.s3-ap-northeast-1.amazonaws.com/manual/base_renkei_manual.pdf) / [NE送り状連携](https://next-engine.net/functions/okurijyo-renkei/)

## 導入順

1. まずメルカリShopsのNE連携を一件で実運用確認。NE登録店舗は直近のAPI確認で0件で、アプリ・店舗接続は未確認。商品マスタの実証は済んでいるが、出品は未実証。
2. BASEはBELLO直接出品を維持し、NEアプリの商品連携をオフにして在庫・受注・出荷だけ導入するか一件で判定。BASEの商品コードとNE SKU、他販路で売れたときの在庫0反映、BASE注文の取込、出荷確定と追跡番号の返送を確認する。アプリ側の在庫送信は最大約20分の目安なので、一点ものを同時掲載する場合の売り越し対策は別途必要。
3. 楽天市場の出店時にNEを標準運用候補とする。ラクマは公式ショップ開設後にNE連携候補とする。
4. ヤフオク非ストア向けには、BELLO内の手動出品補助、販売済み操作、他販路停止の確認タスクを用意する。

NE本体は[料金表](https://next-engine.net/price/)では月額3,000円（税抜、月200受注まで）から。BASE連携アプリは[掲載ページ](https://base.next-engine.org/apps/3150/detail/)で1店舗月額5,000円（税抜）、ラクマ連携アプリは[掲載ページ](https://base.next-engine.org/apps/4380/detail/)で月額5,500円（税込）。導入判断時に料金を再確認する。

## この判断までの作業状態

メルカリShops専用のCSVダウンロード補助の未完成変更は `stash@{0}` に退避した。多販路の共通データ設計を決めるまで配備しない。連携アプリ提供元への問い合わせは送らない。
