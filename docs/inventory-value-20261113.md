# 在庫金額・数量の集計

PCの売上画面とスタッフアプリの「在庫金額」に、金額の円グラフ、その下に数量の円グラフを表示する。両方で同じ5区分・配色を使う。数量は商品ページ数ではなく実在庫の点数。金額は購入単価×数量であり、仕入時に単価へ含めた送料を二重加算しない。

## 集計区分（2026-11-13指定、version 2）

|表示|含むカテゴリ|
|---|---|
|補修待ち|補修待ち、保留|
|撮影待ち|撮影待ち|
|出品待ち|出品待ち、五十嵐さん|
|出品中|販売中、出品中、複数在庫 未出品（空白の有無を許容）|
|業者間|業者間|

業者間と工程の両方が付いている商品は業者間に一度だけ計上する。複数工程が併存する場合は補修→撮影→出品待ち→出品中の順で一度だけ計上し、内部の確認記録を残す。移動予定は重複計上しない。

入金待ち・未入金は売却済みとして金額・数量とも対象外。販売終了日あり、売り切れ、発送完了、出荷指示済、事務所備品、破棄、無償提供、区分未設定も除外する。現行の在庫分け後の数量を使う。単価未入力の商品は金額から除き、数量には含める。明示的な0円単価は有効。

「その他」「月末の売上表との照合」「集計内容の確認」の大きなパネルとカテゴリ設定は表示しない。単価を確認できない商品数のみ末尾に短く表示する。実際の商品カテゴリ・在庫数量・売上データは更新しない。

## 保存と負荷

SalesAggregateSnapshot.inventoryValueJsonに集計結果を保持。currentは既存の12時間ごとの売上集計と同じInventory走査を再利用する。Categoryをまとめて一回取得。数量グラフも同じ集計結果を使い、通信・DB読取を追加しない。APIは既存の認証・sales権限・所有者照合、private/no-storeを維持する。

月末はinventory:YYYY-MM:v2へ一度だけ保存する。旧版のinventory:YYYY-MMは訂正前の記録として保持し、旧合計を新分類として表示しない。JST翌月1日00:00を境界に、既存ZAICO同期アーカイブの全件記録と差分から復元する。現在値で過去の数量を推定しない。連続性の欠落や月末をまたぐ変更で旧値が不明なら書き込まない。同一月・同一版の再実行は条件付き作成で上書きを防ぐ。

月末記録があればS3の再読込を省く。元の同期アーカイブは既存の90日保持のまま。復元失敗はログへ記録し次回に再試行する。未集計・取得失敗を0円として表示しない。

## 検証と公開

- verify-inventory-value.ts: 18ケース。分類、重複、入金待ち、欠損単価と0円、数量割合、空グラフ、旧版拒否、変更前データ維持。5,700件×1,000回の計算測定。
- verify-inventory-value-history.ts: 11ケース。JST境界、差分、分割、削除、欠落、遅延更新、再実行、商品ID対応。
- verify-inventory-value-boundary.cjs: API認証・失敗、共有走査、原子的公開、月末v2の一度だけの保存。
- PC/アプリの型検査・配布ビルド、実データを用いた390px/PC表示、金額→数量の順序、月切替・スクロールを確認する。

公開後に定期集計を一回実行しcurrent/v2月末の金額・数量・5区分の合計を検証する。旧月末記録の不変性も確認する。切戻し時は対応する集計版を使い、商品情報には変更を加えない。現在集計の旧版UIへ戻す場合は旧版集計処理でcurrentを再生成する。
