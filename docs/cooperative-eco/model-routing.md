# GPT・Claude Code の仕事内容別モデル選択

## 実装範囲

ユーザーの元の指示、目的、範囲、要件、受入条件、独立テスト、未解決事項を実装前に構造確認する。意味の一致までは構造検査では保証しないため、GPTの仕様確認・最終QAを引き続き必要とする。

仕事を15種類に分類し、GPTの仕様・QAワーカーとClaude Codeの実装アダプターに共通のモデル選択処理を用意した。Claude側は選択結果を実際のrunner生成に渡す。GPT側はモデルごとに登録されたworkerへ振り分ける。会話への指示だけで現在のデスクトップモデルを変更したことにはしない。

| 仕事 | 担当 | 選択方針 |
| --- | --- | --- |
| 指示確認・仕様・受入条件 | GPT | 品質基準を満たす登録済みモデル |
| 抽出・分類・ログ整理 | GPT | 同じ仕事内容で評価済みの低使用量モデル |
| 文言・定型修正 | Claude Code | 低リスクで評価済みなら低使用量モデル |
| 画面修正・テスト作成・通常実装 | Claude Code | 仕事内容別の実測比較 |
| 複雑な設計・認証・権限 | 該当工程の担当AI | 既存の上位モデル方針を維持 |
| テスト実行・許可済み反映・集計 | ホストプログラム | AIを呼ばない |

## 選択条件

- 同一プロバイダー内のみ。利用枠不足は待機し、モデル変更による回避はしない。
- ホストの独立評価チェックポイントと一致する比較記録のみ採用する。
- 同一評価セット・同一使用量単位、最低30件、成功率95%以上、基準との差2ポイント以内、安全性失敗ゼロ、原則30日以内。
- 成功1件当たりの総使用量 = 1試行の平均使用量 × 平均試行数 ÷ 成功率。再試行で割高になる候補は選ばない。
- API換算額は価格確認日も必要で、実際の請求額として表示しない。
- 比較データ不足、未登録モデル、固定モデル指定、論理失敗後は安価な候補へ変更しない。
- GPTは工程のモデル決定を保存し、再試行で勝手に別モデルへ変更しない。
- 分類は承認ではない。既存の保護対象操作に対する承認制御は継続する。

## 現在の制約と再開地点

モデル名・価格・優劣を推測して登録していない。初期catalogは空なので既存モデルを維持する。今回の比較試験は人工データで選択ロジックを検証したもので、実モデルの優劣・削減率を実証したものではない。

実運用DBのeco migrationは未実施、eco機能は無効。現在のデスクトップQA接続は単一セッションであり、複数のGPTモデルに対応する実worker登録は別途必要。Claude利用枠の回復後、専用環境の既存通し検証を先に完結し、その記録を保全する。モデル比較のために新たな有料APIベンチマークは開始していない。

実際の節約運転を有効にする前に、接続可能なモデルとその実worker、独立した同一課題の評価記録を登録する。30件は実用上の最低条件であり、統計的な同等性を保証する件数ではない。Claude Max等の定額契約では、主な目標は利用枠と待ち時間の節約で、月額料金の減少を意味しない。

新たなDBテーブルや本番リソース変更は追加していない。設定スナップショットと既存checkpointを利用する。
