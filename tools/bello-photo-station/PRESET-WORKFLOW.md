# プリセットを比較して選ぶ運用

## 利用者の操作

1. SDカードを挿すと、未取込のJPEG/ARWを原本のままコピー・照合します。
2. 取込が終わると「仕上がりを比較して選択」が開きます。後からは取込履歴を選んで「仕上がりを選んで処理」で再開できます。
3. 「プリセットを追加・更新」でXMPを登録します。種類数は固定していません。何も登録されていなければ追加待ちになります。
4. 同じ設定を使う写真を左側で選び、代表写真を選びます。初期状態は取込写真すべてが対象です。1商品内で異なる現像設定を使う場合は写真ごとに分けて選択します。
5. 「全プリセットを比較」で、Lightroom標準現像と各プリセットの実際の書き出し結果を並べます。画像をダブルクリックすると拡大できます。
6. 成功したプレビューを選び、「選択した仕上がりを対象写真に設定」を押します。元画像カードや失敗カードは選択確定できません。
7. 画面上部で商品トップ画像を選びます。1回の取込バッチを1商品として扱います。異なる商品を同じバッチへ混ぜないでください。
8. 全写真の選択が揃ったら「このプリセットで全画像を処理・アップロード」を押します。Lightroom現像後に各写真の水平と被写体を判定し、全写真が安全に収まれば正方形、1枚でも正方形に収まらなければ商品全体を3:2で自動処理します。
9. 構図プレビューの生成と承認操作は通常不要です。被写体や水平を確実に判定できない場合は送信前に停止します。その場合だけ「構図を手動で調整」で商品全体を枠で囲み、必要なら水平角を入力して再実行できます。

プリセットの推薦AIは使いません。LightroomのAIマスクは使用します。

## Lightroom接続（最初の一度）

- Lightroom Classic 13.3以降が必要です。実働PCでLightroomにログインし、起動しておきます。
- `Install-LightroomBridge.ps1`を実行すると、ユーザーのLightroom Modulesフォルダーへ連携プラグインを配置します。実行中のLightroomを勝手に終了する処理はありません。
- Lightroomを再起動し、「ファイル → プラグインマネージャー」でBELLO Photo Stationを確認してください。自動表示されなければ「追加」で `%APPDATA%/Adobe/Lightroom/Modules/BelloPhotoStation.lrplugin` を指定します。
- Lightroom Classicを再起動するとBELLO連携は自動開始します。応答が止まった場合だけ「ライブラリ → プラグインエクストラ → BELLO連携を開始」で再開できます。停止も同じメニューです。
- 連携プラグインのコードを更新した場合だけ、実行中の旧コードを読み替えるため「BELLO連携を停止」→「BELLO連携を開始」を実行します。通常の写真取込ごとには不要です。
- 比較画面に登録したXMPと同じプリセットをLightroomにも読み込んでください。今後更新するときも両方を揃えます。
- LightroomはXMPを読み込む際にSDK側へ別のIDを付けるため、連携プラグインは登録XMPとLightroom内プリセットのファイル内容を照合します。名前だけが一致する古いXMPは使いません。
- 既存の編集がある写真を変更しないため、プラグインはジョブごとに作業用コピーをLightroomカタログへ登録します。専用カタログを使うことを推奨します。作業用コピー・カタログ項目の自動削除は未実装です。

## プリセット追加・変更・保存

プリセットは端末rootの `presets/` にUUIDで保存します。同じUUIDを追加すると更新です。名前が同じでもUUIDが異なれば別候補になります。削除したい場合は該当XMPをこのフォルダーから除き、一覧を更新してください。Lightroomの元XMPには書き込みません。

プレビューは `sessions/<id>/comparisons/<comparisonId>/`、選択は `sessions/<id>/selections.json` に保存します。プリセット内容、元写真、出力設定が変わった場合、古い選択では送信せず再比較を要求します。Lightroom内の読み込み済み設定の指紋も比較します。

比較の明るさはLightroomの設定を使用し、Photo Stationの簡易トーン補正は重ねません。出力サイズ・品質・方向補正・メタデータ設定は引き続き使用します。比較用は長辺1600px、最終出力は編集設定で指定したサイズです。RAWの「補正前」はLightroomの標準現像であり、センサーの未現像値ではありません。

## エラー時

- Lightroom未接続、未登録プリセット、現像失敗はエラー表示します。未加工写真を「プリセット適用済み」として代替送信しません。
- プレビュー処理はプリセットごとに最大180秒。失敗したカードは選択できず、ほかのカードは確認できます。
- 再開時は既存の選択・処理履歴を利用します。設定が同じ処理は再現像を省略します。
- 処理中に「後で続ける」で閉じると比較クライアントを停止します。Lightroom内ですでに開始した処理は終了まで続く場合がありますが、自動アップロードはしません。

## 今回含まれない処理

床のゴミそのものの除去とプリセット推薦AIは含みません。床の見え方は `presets/BELLO調整用　床も.xmp` をLightroom ClassicとPhoto Stationの両方に登録して調整します。

構図計算は一様な撮影背景を想定します。色が背景に近い商品や水平線が見えない写真は自動で送信せず、画面で枠と角度を指定します。確定した構図は原本・プリセットの内容と結び付け、変更後の再送は再確認が必要です。

## 実装と検証

- Windows WPF画面 → presetCli.mjs → プリセット登録/比較/選択保存。
- Nodeから版2のデータ専用ファイルキューへ現像要求し、LuaプラグインがSDKの `applyDevelopPreset(...,100,true)` と `LrExportSession` で実行します。版1の既存C#橋渡し契約とは別フォルダー/プロトコルです。
- 原本はコピーして使用し、任意コード実行やクラウドへの写真送信を行わないローカル現像連携です。アップロードは既存の認証・API経路を使用します。
- Nodeの自動テスト67件、.NETの自動テスト39件、WPF Releaseビルド・win-x64 publish成功（2026-09-23）。Lua 5.1構文チェック含む。PowerShell連携インストーラーも構文検査済み。
- **Lightroom本体上のAIマスク再計算・書き出し、実APIへのアップロードを含む通し検証は未実施です。自動テストでは代替レンダラー/通信先を使用しています。**
- 受入れ時は、新規プリセット追加、白い商品で比較、別角度へのマスク再計算、選択後の一括処理、Web表示、接続停止時の保留を実働PCで確認してください。
