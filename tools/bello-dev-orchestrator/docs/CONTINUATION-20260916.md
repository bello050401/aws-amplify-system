## 今回追加した修正

1. **空白・日本語を含む場所からの起動**: 本体の起動引数も既存の引用符処理を通す。子プロセスは非表示。テストを空白なしの代替パスから実際の空白・日本語パスに変更し、本体で使用する起動関数を検証する。
2. **無効なHTTP監視による再起動を防止**: dashboard.enabled=false なら監督側のHTTP復旧処理を省略。CLIは監視対象外と明示し、statusは引き続きプロセス不在を検出する。
3. **応答の健全性確認**: okは真偽値trueのみを受理。不正JSON、文字列のfalse、巨大応答を異常扱い。応答上限64KiB、不正なタイムアウト値を拒否。全アドレス待受はループバックへ検査する。
4. **一時停止の正確化**: 実行中の作業は続行し次の作業から停止することを表示。CLIが保存した一時停止・再開を次の処理サイクルで反映。
5. **停止時の保存**: 実行ループと取込中の保存が終わるまでDBと起動所有権を保持。新しい作業は取得しない。取込処理の重複起動を防止。初期化・復旧失敗時は所有権を解放。
6. **停止待機の上限**: 監督の既存60秒上限では、親だけを終了する処理をPID・開始時刻確認付きの既存子孫終了処理へ変更。上限内に完了しない作業は中断復旧の対象となる。
7. **元の未コミット作業の保護**: worktree作成失敗時の同一ツリーへの代替動作は既定で無効。代替動作を明示しても元に未コミット変更があれば実装を開始しない。

1. **エージェントに依存しないテスト証拠**: 現在の機械ゲートで確認するテスト成否・コマンド終了コードは、主に実装担当の構造化報告に由来する。別Claude審査で再検証する仕組みはあるが、任意の報告だけで信頼できる検証と同一ではない。承認済みローカル検証コマンドをOrchestrator自身が起動し、終了コード・ログ・対象コミットを保存する工程を追加する。

4. **通知**: 現在はダッシュボード内の完了記録・TODO。通知先を設定し、送信待ちの永続記録、重複防止、再送、配信結果を追加する。実装完了・staging成功・要対応を分ける。
