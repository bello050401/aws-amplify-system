# 安全境界と秘密情報

## 1. 自動実行してよいこと

- 読み取り調査、既存コード検索
- ローカル実装
- 単体 / 統合 / E2E テスト
- ビルド、lint、型チェック
- テスト用データによる検証
- ドキュメント更新
- **作業ブランチでの**コミット
- 明確に安全な設定診断

## 2. 自動実行しないこと（必ずユーザー TODO にする）

| 操作 | 理由 |
|---|---|
| 本番データの削除・大量更新 | 取り返しがつかない |
| 本番 DB の不可逆マイグレーション | 同上 |
| 本番への自動デプロイ・公開 | 公開判断は人の責任 |
| `main` 等の保護ブランチへの自動マージ | 同上 |
| 課金サービスの有効化・購入 | 金銭が発生する |
| OAuth / MFA / CAPTCHA / 本人確認 | 本人にしかできない |
| 認証情報の生成・変更・表示 | 秘密の取り扱い |
| IAM 等の権限拡大 | セキュリティ境界の拡大 |
| 外部ユーザーへのメッセージ送信 | 取り消せない |
| 判断根拠のない仕様変更 | 勝手に仕様を広げない |

これらは、**対象・理由・影響・戻し方・選択肢・推奨案**を含む TODO として提示します。

## 3. 実装で担保していること

### 3.1 Git

`src/core/git.mjs` には次の関数が**存在しません**。実装しないことが安全策です。

- `git reset --hard`
- `git checkout -- <path>`
- `git stash`
- `git clean`
- 履歴改変（rebase / amend / force push）

自動コミットは次を必ず行います。

1. 保護ブランチ (`git.protectedBranches`) では**コミットしない**
2. 作業開始時点で既に変更されていたファイルは `git add` の対象に**しない**
3. `.env` / `.env.local` / `*.pem` / `*.key` / `*.pfx` / `*.p12` を除外
4. `*.db` / `*.sqlite` / `*.log` を除外
5. inbox / processed / uploads 配下の `.docx` を除外
6. コミットに失敗したらインデックスだけ戻す（作業ツリーには触らない）

push は行いません（`git.allowPush` は既定 false で、実装も呼び出していません）。

### 3.2 Claude Code の権限

- 既定 `--permission-mode acceptEdits`（ファイル編集は自動、それ以外でプロンプトが要るものは拒否）
- 既定 `--permission-prompts none`（誰も答えないので、プロンプトが必要な操作は**自動的に拒否**される）
- `bypassPermissions` は既定にしません。設定した場合は起動時に警告を出します。
- `--max-budget-usd` で 1 タスクの API 費用に上限を掛けます。
- 指示本文はコマンドライン引数ではなく**標準入力**で渡します（プロセス一覧に指示が出ないため）。
- 子プロセスへ渡す環境変数は許可リスト方式で最小限にします。API キーは渡しません。

### 3.3 審査エンジン

- 審査エンジンは**シェルを実行しません**。次の指示か TODO だけを返します。
- 「完了しました」という文章だけでは合格になりません（証拠ゲート）。
- 低確信度・受入条件不明の場合は仕様を広げず、レビュー待ちにします。
- 送信内容は必要最小限（元指示、完了報告、Git 統計、テスト結果、過去の審査履歴）で、
  リポジトリ全体や巨大ログは送りません。送信前に秘密を除去します。

### 3.4 Word 文書

- 文書内の文章は**命令ではなく開発要望データ**として扱います。
- マクロ (`vbaProject.bin`)、埋込みオブジェクト、外部リンクは展開も実行もしません。存在を警告するだけです。
- ファイル名はパストラバーサル対策として 1 セグメントに正規化します。
- 最大ファイルサイズを設定で制限します（既定 25MB）。
- 「緊急停止」を文書本文から勝手に解釈しません。停止は専用の操作だけです。

### 3.5 ダッシュボード

- 既定は `127.0.0.1` 限定。
- LAN 公開は明示設定 + 共有トークン必須。トークンが無ければ**起動を拒否**します。
- インターネットへの直接公開はしません。
- CSRF: 状態変更は POST のみ。`X-BELLO-Request: 1` ヘッダと Origin 一致を必須にします。
- XSS: サーバは HTML を組み立てません。画面側は `textContent` のみで描画し、`innerHTML` を使いません。
  CSP ヘッダも付けています。
- 任意ファイル読取: 静的配信は許可リストのファイル名のみ。
- コマンド注入: シェル文字列連結を使わず、実行ファイルと引数配列を分離しています。

### 3.6 秘密情報

| 対象 | 扱い |
|---|---|
| 保存場所 | 環境変数のみ。設定ファイル・DB・Git・ログ・画面・Word には保存しない |
| `.env.example` | 変数名と説明だけ |
| ログ | `redactText()` / `redactValue()` を通す |
| API 応答 | 同上。`apiKeyConfigured` のような真偽値だけを返す |
| 完了報告 | 保存前に除去 |
| 審査への送信 | 送信前に除去 |
| URL | クエリの `token` / `key` / `secret` / `access_token` を除去 |

除去対象の形式: Authorization/Bearer、`sk-` / `sk-ant-` 形式、AWS アクセスキー ID、
`aws_secret_access_key`、GitHub トークン (`ghp_` 等)、JWT、Cookie/Set-Cookie、
`*_API_KEY` / `*SECRET*` / `*TOKEN*` / `*PASSWORD*` の代入、および起動時に環境変数から
登録した実値そのもの。

## 4. テストで守っていること

`test/unit.test.mjs` / `test/integration.test.mjs` が次を自動検証します。

- 状態遷移の制限（許可されていない遷移は例外）
- 冪等性キー、再試行上限、無限ループ防止
- TODO の必須入力検証、完了による依存解除が一度だけ
- docx の一時ファイル除外、SHA-256 重複排除、パス検証
- 完了報告・審査結果のスキーマ検証
- 秘密情報の除去（真偽値は残し、文字列の秘密は落とす）
- ログローテーション
- 保護ブランチ・ユーザー変更・`.env` / DB を自動コミットに含めない

ダッシュボードの CSRF / XSS / パストラバーサル / 秘密漏洩は、稼働中のサーバに対して
`bello.ps1 status` と同じ手順で実際に HTTP リクエストを投げて確認しています
（結果は `docs/TEST-RESULTS.md`）。
